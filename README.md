# 痒痒鼠解放双手 使用指南

## 一、怎么打开

找到文件夹里的 **yys_auto.exe**，**双击运行**即可。

> 💡 建议右键 →「以管理员身份运行」，部分电脑不这样做可能点不了游戏窗口。
>
> 💡 首次打开稍慢是正常的。

程序启动后会自动弹出一个浏览器窗口，这就是控制面板，所有操作都在这里完成。

**紧急停止**：按键盘上的 **F12**，所有实例立刻停。也可以点卡片上的 **⏹ 停止** 单独停一个。

> F12 是控制面板页面里的按键监听，不是系统级热键。按之前先用鼠标点一下控制面板，确保焦点在页面上；焦点停在模拟器或游戏窗口里时，按 F12 不会有反应。
>
> 另外 `python autoclick.py`（脚本模式）注册的是真正的全局热键 F12，那个在任何窗口下都管用。

## 二、开始之前的准备工作

### 模拟器兼容性

本工具**同时支持 MuMu 模拟器（普通版）与阴阳师 MuMu 专版**，两者均可正常运行。

> 仍**建议优先使用普通版 MuMu 模拟器**，专版不作为首选运行环境。

### ⚠️ 路径不能含中文

模板图片的**完整路径**中只要出现中文字符，程序就读不出来（Windows 下 OpenCV 不支持非 ASCII 路径），表现是模板列表看不到图、或者运行时识别一直失败。

请务必遵守：

- **场景名只能用英文或数字**（场景名就是文件夹名），例如 `chi`、`hunwang`、`999`，不要用「痴」「魂王」这类中文名
- **导入的图片文件名同样不能含中文**，建议用英文或数字
- 程序所在的文件夹路径也建议全英文，避免连带踩坑

> 中文路径支持已列入待修复清单（见「已知问题」第 2 条），在此之前请务必按上述规则命名。新建场景时程序会直接拦下中文名，导入模板时中文文件名会被自动改成英文，但**已经存在的中文目录仍需手动改名**。

### 你需要准备：按钮截图（模板）

程序靠「看」屏幕找按钮，所以你得先告诉它按钮长什么样。

**方法一：手动导入图片（推荐）**

1. 打开游戏，停在要截按钮的画面
2. 用系统截图工具（`Win + Shift + S`）或 QQ / 微信截图，框选按钮区域
3. 把截图保存为 `.png`，**文件名用英文或数字**
4. 切到控制面板，点「模板管理」页签
5. 上方选一个场景（没有就点「＋ 新建场景」，**场景名要英文**）
6. 找到要放这张图的**阶段卡片**，点卡片里的「📁 导入本地」，选中刚保存的图片

新建场景默认给你两个阶段：`01_start_begin`（开始）和 `02_end_result`（结算）。开打前的按钮进 `start`，结算页的按钮进 `end`；中间还有别的页面，就在「模板管理」里点「＋ 新增阶段」自己加。

> **开始阶段和结束阶段的截法不一样**：
> - **开始阶段**：只截**按钮本身**，范围越小越好，背景越少越好
> - **结束阶段**：截**按钮 + 周围背景**，结算画面整体变化大，光有按钮容易认不稳
>
> | 类型 | 示例 |
> |------|------|
> | 开始阶段（只截按钮） | ![开始阶段示例](templates/chi/01_start_begin/QQ20260423-131442.png) |
> | 结束阶段（按钮+背景） | ![结束阶段示例](templates/chi/02_end_result/QQ20260804-180021.png) |

**方法二：用程序自带的截图**

不用另开截图工具，点阶段卡片里的「📷 截取」，在弹出窗口里拖一下框就完事。操作细节见下面「截图功能怎么用」。

> **关于「基准图」（baseline）**：程序需要一个场景的**完整窗口截图**当缩放参照。状态显示「未设置」时，点旁边的「📷 截图」直接截一张（绑定窗口时截的就是那个窗口），或者用「📁 导入本地」上传一张游戏窗口的完整截图（**文件名同样不要含中文**）。
>
> 旁边的「🧩 生成初始占位图」会写一张 1×1 的灰图占位，方便先把场景建起来、之后再拿真截图覆盖。它只管 baseline，阶段标志不用手动生成，新建阶段时已经自带。

### 模板管理页上都有什么

顶部一行选场景，右边是「＋ 新建场景」和「🗑 删除场景」。

往下是「窗口基准图」卡片，三个按钮：导入本地、截图、生成初始占位图。

再往下是阶段列表，一个阶段一张卡片：

| 位置 | 内容 |
|------|------|
| 卡片头 | 序号、标签（开始 / 中间 / 结束）、名字、key，右侧 ↑ ↓ 编辑 删除 |
| 左栏 | 阶段标志缩略图，配「📁 导入」「📷 截取」 |
| 右栏 | 按钮模板的缩略图墙，配「📁 导入」「📷 截取」 |

每张按钮模板卡片上还有两个东西：

- 右上角的 ✕，删掉这张模板
- 底部的「⏸ 停用 / ▶ 启用」。停用后这张图运行时不再参与匹配，但文件还在原处。某张图截坏了暂时不想删、或者同一按钮留了新旧两版想先留一版，用这个

顺序是定死的：开始页永远第一条，结束页永远最后一条，只有中间阶段之间能用 ↑ ↓ 对调。

> 从老版本升上来的不用手动整理：打开模板管理时，旧的 `begin/`、`end/` 目录和 `stages/` 那套布局会自动改成新结构，已有文件不会被覆盖。

> 删除是不可恢复的：删阶段会连它的标志图和整个模板目录一起删掉，删场景会把整个场景目录端掉，都不进回收站。删之前没底的话，先把 `templates/<场景名>/` 整个复制一份出来。

### 阶段标志图怎么截

阶段标志是这个阶段的身份证。程序每帧拿它跟屏幕比一下，就知道当前停在哪一页。有了它，识别开销只跟阶段数量有关，跟模板数量无关。

它和按钮模板是两回事，别混：

|  | 阶段标志 | 按钮模板 |
|---|---|---|
| 干什么用 | 判断现在是哪一页 | 匹配到就在那块位置点一下 |
| 一个阶段要几张 | 一张 | 可以很多张 |
| 典型内容 | 状态条、结算标题、页面边框 | 按钮本身 |

设置方式有两条，都在阶段卡片左栏：

- 「📷 截取」：弹出框选窗，框住那一块 UI，回车
- 「📁 导入」：用系统截图工具截好，选中文件上传

选图照着这几条挑，基本不会白配：

- **这一页出现时它一定在**，别的页面不该有。两页都有「确定」按钮，就别拿那个按钮当标志
- 位置固定，不会被弹窗、飘字、特效盖住
- 别框倒计时、伤害数字、随机立绘这类每帧都在变的东西
- **短边至少 20px**。再小会被当成「未设置」的占位图：导入时直接拒收，截图时也会提示你重新框
- 范围不用大，一条状态栏、一行标题就够

没设标志的阶段是认不出来的：加载模板时日志会写「阶段标志未设置，运行时认不出这一页」。一个场景里所有阶段都没标志时，点开始会直接报错停下，提示你先去设置。

想换一张，重新截或重新导入就行，同名覆盖，卡片上的缩略图会跟着刷新。

### 截图功能怎么用

三个入口，行为不一样：

| 按钮 | 在哪 | 存成什么 |
|---|---|---|
| 📷 截取 | 阶段卡片左栏，标志图下面 | 该阶段的标志图 `<key>.png` |
| 📷 截取 | 阶段卡片右栏，模板区下面 | 一张按钮模板 `capture_年月日_时分秒.png`，不覆盖旧的 |
| 📷 截图 | 基准图卡片 | 整张画面直接存成 `baseline.png`，不弹框选窗 |

前两个点完会弹出框选窗：

- 在图上按住左键拖出矩形，松手定住，框上会标出坐标和尺寸
- **滚轮**缩放，10% 到 300%，信息栏实时显示当前比例；图比窗口大时会先自动缩到能看全
- **Enter** 确认，**Esc** 取消并关窗
- 框得太小（宽或高不到 5px）会被当成误触丢掉，再按 Enter 会提示重新框

截的范围取决于这个场景有没有绑定窗口：

- 场景正被某个 Bot 实例用着，而那个实例里选了游戏窗口：**只截那个窗口**，框选坐标就是窗口内的位置
- 没有实例给这个场景指定窗口：**截整屏**

框选窗刚打开时会闪一下，这是正常的。抓屏那一瞬间程序先把自身所有窗口藏起来，抓完立刻还原，所以截出来的图里不会有这个框选窗。抓屏失败时信息栏直接写原因，比如窗口已经关了、或者它指向了控制面板本身。

### 按钮截图要注意什么？

- 截**清晰**的按钮部分，不要带太多背景
- 一个按钮可以存多张图（不同角度、不同状态），提高识别率
- 图片格式用 **.png**

### ⚠️ 关键注意事项

截图模板时，**模板内的每一个像素都可能被脚本点击**。如果截图范围覆盖了能弹出二级界面的区域，一旦误触弹窗遮挡画面，会导致后续识别全部失败。

截图时务必避开以下位置：

| 位置 | 风险区域 | 说明 |
|------|----------|------|
| 右上角 | 聊天入口 | 误点会弹出聊天窗口，遮盖大半画面 |
| 左上 / 中间 | 御魂/式神弹出提示 | 悬浮的御魂图标或式神提示，点开会进入详情界面 |
| 左下角 | Buff 状态栏 | 点击图标可能展开状态详情或叠加界面 |

> 截图范围尽量精确，只框住目标按钮本身，别捎带无关的 UI。

## 三、开始挂机

1. 打开游戏，停在准备战斗的界面
2. 回到控制面板，确认「控制面板」页签已选中
3. 找到你的 Bot 实例卡片
4. 点 **▶ 开始**

之后程序按阶段自己往下走：认出当前停在哪一页，就在那一阶段的可点区域里点一下，等画面翻过去再继续。点中 `end` 那一页算打完一把，回合数 +1。

## 四、控制面板怎么看

### 卡片上的设置

名字点一下就能改。下面三样改完立刻生效：

| 设置 | 说明 |
|------|------|
| 窗口 | 选要点的游戏窗口。下拉里是空的就点旁边的 🔄 刷一下 |
| 场景 | 这个实例用哪套模板 |
| 战斗次数 | 打多少把自动停 |

### 每个 Bot 卡片的按钮

| 按钮 | 干什么的 |
|------|----------|
| ▶ 开始 / ⏸ 暂停 / 🔄 继续 | 三合一主按钮，按当前状态自动切换：空闲时是「开始」，运行中变成「暂停」，暂停后变成「继续」。**暂停不会丢统计**，继续后接着累计 |
| ⏹ 停止 | 结束本轮挂机，卡片回到初始状态 |
| ✕ | 删掉这个 Bot |

### 实时数据解释

| 显示 | 意思 |
|------|------|
| 回合 | 已经打了多少次 |
| 均回合 | 平均每回合花了多久 |
| 战斗 | 平均打一次要多久 |
| 耗时 | 已经挂了多少时间 |
| 预计剩余 | 按当前速度，还要多久打完 |

卡片下方的**散点图**是最近点击位置的分布。每个阶段一种颜色，图例写着「序号 + 名字」。背景里的**半透明轮廓**是程序给那一阶段学出来的「可点击范围」，和散点同色。正常情况下点都落在自己颜色的轮廓里；跑到轮廓外，说明范围学歪了或者识别出了异常，重截一次模板或阶段标志。

### 战斗次数

每个 Bot 卡片上可以单独设置「战斗次数」，比如设 10 次，打完就自动停止。

## 六、参数配置（一般不用改）

切换到「⚙ 参数配置」页签可以调整一些高级设置，改完点底部的「💾 保存全局配置」才生效。

「↩ 恢复默认」会把这份配置整个推倒重来，**连实例列表一起还原**，多加的窗口和它们各自选的场景都会没掉（模板文件不受影响，还在 `templates/` 里）。

### 匹配阈值

默认 **0.75**。

| 情况 | 怎么调 |
|------|--------|
| 按钮经常识别不到 | 调低（如 0.65） |
| 经常点到别的地方 | 调高（如 0.85） |

### 休息设置

| 设置 | 默认 | 说明 |
|------|------|------|
| 每打N把休息 | 50 | 按**打完的把数**算（一把 = 点中开始页 → 点中结算页）。到数后等这一把结束、回到结算界面才歇 |
| ± 浮动 | 10 | 不会每次都刚好 50 把，会随机浮动（更自然） |
| 休息时长 | 30 秒 | 每次歇多久 |
| ± 浮动 | 5 秒 | 休息时间也会随机浮动 |

### 鼠标速度

| 设置 | 默认 | 说明 |
|------|------|------|
| 最小速度 | 1500 | 鼠标移动速度下限，越低越拟人 |
| 最大速度 | 2000 | 鼠标移动速度上限 |

### 扫描与保护

| 设置 | 默认 | 说明 |
|------|------|------|
| 未匹配超时 | 8 秒 | **非战斗状态**（开始界面 / 结算界面 / 加载切图）下，连续这么久没识别到任何按钮就算一轮失败，停顿后重试，3 轮都失败才停止 |
| 战斗超时上限 | 240 秒 | 点中开始页之后，最多等多久还没点到结算页就停。**实际值 = min(平均战斗时长 × 3, 本项, 240 秒)**，按历史均值自动收紧；还没打过时直接用本项。硬上限固定 240 秒，填更大也按 240 算 |
| 未匹配延时 | 2 秒 | 上面每轮失败后停顿多久再试 |
| 同阶段点击上限 | 10 | 连续点了同一阶段这么多次、界面还是没变化，就判定为被遮挡或点击失效，自动停止运行（填 0 关闭该保护） |

> 两个超时各管一段：从点中开始页到第一次点中结算页之间只受「战斗超时」约束（这一段本来就没有可点目标，不会因为没识别到而报错）；其余画面只受「未匹配超时」约束。

### 其他设置

| 设置 | 默认 | 说明 |
|------|------|------|
| 消抖帧数 | 2 | 识别到按钮后，连续确认几帧才点击。调大减少误触，但反应变慢 |
| 识图缩放 | 0.5 | 截图缩小到一半再识别，加快速度。不建议改 |

## 七、常见问题

### 打开程序没反应？

系统需要 **Edge 浏览器**，Win10 / Win11 自带，不用担心。

### 按钮识别不到？

1. 检查**场景名和图片文件名是否含中文**，含了就直接读不到（见上文「路径不能含中文」）
2. 检查模板是否放对了场景目录
3. 把「匹配阈值」调低一些
4. 多截几张不同状态的按钮图

### 点「📷 截取」没反应，或者截图里没有游戏画面？

- **提示找不到窗口**：场景绑定的那个窗口已经关了。程序不会偷偷退回整屏，因为整屏图和运行时的窗口截图尺度对不上，那样的模板是废的
- **截出来是一片桌面**：游戏窗口被别的程序挡住了。截图抓的是屏幕上的画面，先把遮挡物挪开再截
- **框选窗闪了一下才回来**：正常。抓屏那一刻程序会先把自己的窗口藏起来，抓完再放回去

### 挂了没多久就自己停了？

翻一下卡片上的日志，如果结尾是「连续 N 次点击 xx 阶段后界面无变化，判定为点击失效或被遮挡」，说明有东西挡住了画面（常见是弹出的二级界面、聊天窗口、系统通知），程序为了避免继续乱点会主动停下。

- 手动关掉弹窗，再点「开始」即可
- 如果每轮都这样，多半是**游戏界面变了**导致模板或阶段标志过期，重新截一次即可
- 嫌它太敏感，可以把「同阶段点击上限」调大，或填 `0` 关闭该保护

### 设置了阶段标志，反而识别不到了？

标志图选得不够独有。要求是这一页出现时它一定在，别的页面不该有：

- 别拿按钮图当标志，要挑该阶段独有的界面元素，比如状态条、结算标题
- 太小的图标容易被特效或遮挡影响，选**大一点、颜色稳定**的区域
- 没有可用标志的阶段是认不出来的，运行一到这一页就卡住。全部阶段都没标志时程序会直接拒绝启动并提示你先去设置

### 鼠标不动、点不动，或日志显示点击但游戏没反应？

先看日志里有没有这一条（三处日志格式统一为 `时间 | 来源 | 级别 | 消息`，文件带日期、控制台与面板只到时分秒）：

```
2026-11-02 23:22:46 | yys.bot1         | WARNING | ⚠ 权限不匹配：游戏以管理员身份运行，本程序未提权
```

有的话就是它。Windows 的 UIPI（用户界面特权隔离）会**直接丢弃**低权限进程发往高权限窗口的鼠标点击，表现是日志一直在滚「🖱 点击」，游戏却毫无反应，窗口也置顶不了。

处理：关闭程序 → 右键 → **以管理员身份运行**（或者让模拟器不以管理员启动，两边权限一致即可）。

其他可能：

- 部分游戏需要在显示设置里关掉「硬件加速」
- 游戏窗口被其他窗口挡住时识别会失效（截图抓的是屏幕区域，不是窗口内容），把游戏窗口露出来
- 日志里出现「鼠标点击执行失败」，把那行发出来，是 pyautogui 层面报错

### 杀毒软件报警？

正常现象。程序需要模拟鼠标和监听键盘，安全软件可能误会。添加到信任列表就好。

> 产物 `yys_auto_app\yys_auto_v1.3`（约 287 MB）。已验证：exe 清单含 `requireAdministrator`、无 `asInvoker`；包内不含 `templates` 与 `config.json`（首次运行自动生成）；实际双击启动可正常开出窗口并写 `logs\yys_auto.log`；因高完整性运行，非提权 shell 无法结束该进程。

- 🐛 **修复「日志显示点击、鼠标却没动」**：鼠标执行线程遇到一次 pyautogui 异常（典型是光标停在屏幕四角触发 FAILSAFE）就直接死掉，之后所有点击只进队列不执行。现在单次点击失败只记日志、线程不再退出，并加了存活检查、自动重启、队列积压告警，以及光标压在角落时的自解锁
- 🐛 **修复点「开始」后游戏窗口不到前台**：原来只调一次 `SetForegroundWindow` 且不检查返回值，被系统前台锁拒绝也毫无提示。现改为附到前台线程 → 注入 Alt 键 → 临时置顶 → 兜底切换四级尝试，每级都用 `GetForegroundWindow()` 校验
- ✨ **权限自检**：首次找到窗口时比较游戏进程与本程序的权限级别。游戏以管理员运行而本程序未提权时，Windows 的 UIPI 会丢弃点击，日志会给出明确告警。本版起程序默认以管理员身份启动
- 🔧 **GUI 也写日志文件**：此前 `setup_root_file_logger()` 只在命令行入口调用，打包成 exe 后没有任何落盘日志。现在启动即在程序目录 `logs\yys_auto.log` 记录（5MB 轮转，保留 3 份）
- 🔧 **打包脚本不再复制源码 `templates`**：场景模板由用户在控制面板里维护，程序首次运行自动创建空目录
- 🐛 **修复「一直看到 begin 却迟迟不点」**：旗帜模式下每帧都在可点击区域内重新随机采样，而消抖判定「同一目标」用的是「两次中心点相距 <25px」，随机点之间几乎永远超距，确认计数攒不满，只能靠运气凑巧才点击（日志表现为连刷十几条「采样点」才出现一次「点击」，实测 16 次判定只成功 3 次，单次点击延迟 0~4 秒抖动）。现在区域采样点只按阶段类别计数——连续 2 帧旗帜仍判为同一阶段即点击；固定模板模式保留原来的位置比较
- 🐛 **修复按下停止后鼠标还在动**：停止只置了 Bot 的退出标志，而鼠标执行线程用的是另一个停止事件，队列里已积压的点击会照常执行完。现在点停止会立即丢弃该实例尚未执行的点击（多开时只丢自己投递的那部分，不影响其他实例），丢弃条数会写进日志
- 🔧 **日志格式统一**：文件日志、命令行控制台、控制面板日志面板此前各用一套格式（`时间 | 名字 | 级别 | 消息`、`[名字] 消息`、`时分秒 消息`），同一条事件三处长不一样，没法逐行对照。现在共用同一模板 `时间 | 来源 | 级别 | 消息`，只有时间精度不同：文件带完整日期，控制台与面板只到时分秒。模板加载的 `[baseline]` 提示也从 `print` 改成正式日志
- 🐛 **修复 GBK 控制台下 emoji 日志被吞**：日志里带 🖱 ✅ ⚠，而 Windows 控制台默认 GBK 编码写不出这些字符，logging 会静默丢掉整条消息并打一行「--- Logging error ---」。现在控制台流以 UTF-8 + `errors="replace"` 重包，命令行模式不再丢日志
- 🐛 **修复打包后双击就报 `ImportError: DLL load failed while importing _ctypes`**：conda 把 `ffi-8.dll`、`libssl-3-x64.dll` 这类第三方 DLL 放在 `Library\bin`，不在 PyInstaller 的默认搜索路径里，于是扩展模块（`_ctypes.pyd`、`_ssl.pyd` 等）进了包、它们依赖的 DLL 却没进，程序在 matplotlib 的启动钩子里直接崩掉并弹错误框。现在 `yys_auto.spec` 显式收集这些 DLL（ffi / libssl / libcrypto / libbz2 / liblzma / libexpat / libmpdec），`build.ps1` 也会先把 conda 的 `Library\bin` 加进 PATH 再调用 PyInstaller
- 🐛 **未匹配判定改为「时长」**：原来是数次数（`miss_threshold`），但扫描间隔在 0.25~1.0 秒之间浮动，同样 20 次对应 5~20 秒不等，长线副本里极易误判退出。现改为记录「最后一次匹配成功的时刻」，连续超过设定秒数才算一轮失败，与扫描快慢彻底解耦。参数更名为「未匹配超时」（默认 8 秒），旧配置里的 `miss_threshold` 会按 0.3 秒/次自动折算
- ✨ **新增「战斗超时」参数**（默认 240 秒）：从点中 begin 到第一次点中 end 之间单独计时，这段本来就没有可点目标，不再计入未匹配。长线副本（2~3 分钟）可调到 300~360，避免被误杀；真正卡死时该超时会直接停止并说明原因。休息/暂停期间战斗计时自动顺延，既不消耗超时额度，也不计入战斗时长统计
- 🐛 **修复「连续未匹配上限」调大后失效**：`run()` 里有一段硬编码的 `error_score >= 30` 防卡死判断，会在重试逻辑之前抢先把线程干掉，导致阈值调到 40 时约 20 次就退出、3 轮重试永远走不到。现已删除该硬编码，退出判定改为三套各管一事的机制：未匹配（时长）、连续截图失败（20 次）、连续识别异常（10 帧）；`error_score` 只保留用于日志与窗口激活节奏
- 🐛 **休息改为按「把数」触发**：原来看的是 `click_count`（begin 和结算界面的每次 end 都算一次点击），设「每 50 把休息」实际约 12~20 把就歇了。现改为按 `round_count`（一把 = begin → 下一次 begin）；且达到把数后会等本把战斗结束（点中 end、回到结算界面）再休息，不会打断战斗
- 🔧 **休息/暂停期间战斗计时自动顺延**：既不消耗「战斗超时」额度，也不计入战斗时长统计，避免休息 30 秒被误算成战斗变长
- 🔧 **结算界面稳定等待由 2 秒延长到 3 秒**（`REGION_LEARN_SETTLE_SEC["end"]`）：结算动画尚未播完就开始学习可点击区域，会把过渡帧的匹配结果一并学进去，导致 end 的点击范围偏小甚至学失败
- 📝 **文档更新**：模拟器支持说明由「仅支持普通版、不兼容专版」改为「普通版与阴阳师专版均支持，建议优先使用普通版」；参数说明同步为两个超时

# 发版打包

## 版本号约定

- **打包前**：所有未发布的改动都记在**同一个版本号**下，后续改动继续往该版本追加条目
- **打包后**：该版本号冻结，之后的改动开**下一个版本号**
- README 顶部的「当前版本」始终指向**正在开发中**的那个版本

> 例：v1.1 打包发布后 → 之后所有改动都写进 v1.2 → v1.2 打包后 → 再开 v1.3

## 目录约定

所有发布版本统一归档在 `Mycodes/yys_auto_app/` 下，按版本号建目录：

```
Mycodes/
├── yys_auto/                  ← 源码仓库
└── yys_auto_app/              ← 发布目录
    ├── yys_auto_v1.0/        历史版本
    ├── yys_auto_v1.1/        历史版本
    ├── yys_auto_v1.2/        历史版本
    └── yys_auto_v1.3/        最新发布版本（已冻结）
```

每个版本目录内含：

```
yys_auto_v1.3/
├── yys_auto.exe      ← 双击运行
├── _internal/        ← 程序依赖，不要动
├── config.json       ← 配置（前端保存时自动写这里）
├── templates/        ← 模板截图
├── logs/             ← 运行日志
└── README.md         ← 本说明
```

## 打包命令

```powershell
cd c:\MyAPPs\Mycodes\yys_auto
.\build.ps1 -Version 1.3
```

版本号**只写数字**（`1.3`，不是 `v1.3`）。脚本会自动完成：

1. 调用 PyInstaller，输出到 `yys_auto_app/yys_auto_v1.3/`
2. 清理发布根目录残留的中间 exe
3. 复制 `config.example.json` 和 `README.md` 进发布目录。本机的 `config.json` 不带（含窗口名等信息），源码里的 `templates/` 也不带，都靠用户首次运行时自己生成
4. 创建空的 `logs/` 目录

目标目录已存在时会直接报错，避免误覆盖旧版本。

## 手动打包（等价命令）

```powershell
cd c:\MyAPPs\Mycodes\yys_auto
$env:YYS_APP_VERSION = '1.3'
pyinstaller yys_auto.spec --distpath ../yys_auto_app --workpath build --noconfirm
```

输出目录名由 `yys_auto.spec` 里的 `COLLECT(name=f'yys_auto_v{_VERSION}')` 决定，版本号经环境变量 `YYS_APP_VERSION` 传入（未设置时为 `dev`）。

> 打包中间产物 `build/` 会保留在源码目录，可加速下次打包；不需要时直接删除即可（已在 `.gitignore` 中忽略）。

# 已知问题

> 以下问题当前版本尚未修复，仅作记录。

## 1. 程序存在最大存活时间，超时后失去连接

**现象**：程序持续运行一段时间后会失去连接（前端控制面板无响应 / 状态轮询失败），需重启程序才能恢复。

**影响**：长时间挂机场景下无法稳定运行，需要人工干预重启。

**排查方向**：

- Eel / WebSocket 连接超时或内存泄漏
- 日志缓冲区无限增长导致内存耗尽
- 长时间运行后句柄/资源未释放
- gevent 相关的定时器或 keep-alive 机制超时

## 2. 中文路径下模板图无法读取

**现象**：模板图片路径包含中文字符时（仓库里就有一个现成的例子：`templates/魂土/`），程序读不出里面的模板图，识别一直失败。

**影响**：场景目录使用中文名时功能异常，只能用英文命名场景规避。

**排查方向**：Windows 下 OpenCV（`cv2.imread`）不支持非 ASCII 路径，可改用 `cv2.imdecode(np.fromfile(path, dtype=np.uint8), flag)` 读取，模板加载与截图保存两处需统一处理。

# 接下来的优化想法

> 后续版本的改进计划。

## 多阶段标志与多点击区域（v1.4 已实现，保留设计说明）

> 这套方案已在 v1.4 落地：阶段列表、按阶段学习可点击区域、固定「开始→中间页→结束」的顺序都已可用，下列内容保留为设计背景；「需要动的地方」一节记录的是改动前的旧代码形态。

**要解决的场景**：一场战斗的开始 / 结束界面不一定是单一画面。结算尤其明显，常见是「MVP 展示页」→「奖励结算页」两个环节，各自都要点一次；现在每个阶段只能配一张标志 + 一个点击区域，第二个界面命不中标志，或者继续按旧区域乱点。

**方案：按顺序命名的阶段列表**

阶段数量不多（多数副本就三个），所以不做「标志集合 + 优先级」，直接排成一列。命名固定三段：**序号_标签_名字**。

- 标志图 `<NN>_<tag>_<name>.png`，同名目录放该阶段可点击的按钮模板
- `NN` 两位数字，从 `01` 起连续编号，排序就按它解析成整数比（不直接比字符串，否则 `1_`、`10_`、`2_` 会乱序）
- `tag` 表示这一阶段在流程里的角色：`start`（战斗开始）/ `end`（一把结束）/ `mid`（中间的其它页面，默认）
- `name` 用小写英文 / 数字 / 下划线，描述这一页是什么（`begin`、`mvp`、`reward`）
- 新建场景时程序默认建好 `01_start_begin`、`02_end_result` 两个阶段，开箱即用

```text
templates/chi/
├── baseline.png
├── 01_start_begin.png      ← 阶段标志图
├── 01_start_begin/         ← 该阶段的按钮模板
│   └── btn_start.png
├── 02_mid_mvp.png          ← 后续添加的中间页（编号已重排）
├── 02_mid_mvp/
│   └── btn_skip.png
├── 03_end_result.png       ← 一把到这里才结算
└── 03_end_result/
    └── btn_confirm.png
```

**识别规则**：

- 每帧同时检测**全部**阶段标志（一般 3 张，开销可忽略），不用只盯着「当前 + 下一个」
- 命中哪个就点它对应的区域 → 某次没出现的阶段自动跳过，不会因为顺序卡死
- 用序号做单调约束：只接受「序号 ≥ 当前进度」的命中，避免命中上一阶段的残留元素时来回点
- 命中后把进度推进到该序号

**点击后复检（同阶段可能要点两三次）**：

- 命中阶段 → 点击 → 等 300~500ms → 重新截图
- 同一阶段标志仍在（分数够）→ 再点一次，计数 +1，间隔按 0.5s → 1s → 1.5s 退避
- 标志消失或命中更高序号 → 推进到下一阶段
- 连点上限沿用「同阶段连击上限」（默认 10），超了判点击失效并停止
- 冷却时机要跟着改：`_begin_cooldown_until` 不能在点击时立刻设置（首次 3 秒会把第二次点击挡掉），改为「确认离开该阶段」时才设

**计时与轮次**：

- `tag=start` 的阶段命中 → 开表；`tag=end` 的阶段点中 → 一把结束（结算战斗时长、`round_count + 1`、检查是否该休息）
- `tag=mid` 的阶段只管点击，不参与起止判定
- `start` 和 `end` 各最多一个，标了两个直接报错；两者都没配时退化为位置兜底（第一个当 start、最后一个当 end），旧模板不会失效
- 中间出现几个结算页都算同一把战斗，不切断计时

**阶段管理（前端）**：

- 新建场景时默认只建**第一个**和**最后一个**阶段（`01_start_begin`、`02_end_result`），绝大多数场景就这两个够用
- **增加阶段**：弹窗只问阶段名（如 `mvp`），标签固定为 `mid`（中间页），用户不用理解标签概念；编号按当前最大序号 +1 自动生成
- **修改阶段**：改名、改标签（开始 / 中间 / 结束）、换标志图、管理按钮模板，都在同一个编辑弹窗里
- 新建场景和新增阶段都按「占位图 + 同名目录」建：按钮模板目录先空着，标志图写一张 1×1 占位（沿用 `_write_placeholder_png`，短边 < 20px 即视为「未设置」），用户用真实截图覆盖即可
- **调整顺序**：上移 / 下移（或拖拽），程序把标志图与同名目录一起重命名，编号始终重排成 `01..NN` 连续
- **删除阶段**：删掉标志图与目录后同样重排，不留空号
- 重命名要先改成临时名、再改成终名，避免 `02 ↔ 03` 互换时互相覆盖
- 校验：名字非空、只用小写字母 / 数字 / 下划线、不与已有阶段重名；`start` / `end` 各最多一个。不通过就直接提示、不创建
- Bot 运行中禁止增删和排序（先停止），否则正在用的阶段列表与区域缓存会错位

**前端界面（模板管理页）**：

场景详情页从现在的「begin / end 两张卡片」改成一张阶段列表，每行：

| 列 | 内容 |
|---|---|
| 序号 | `01`、`02`…，排序后自动重排 |
| 标签 | `start` / `mid` / `end` 小徽章 |
| 名字 | 用户填的 name |
| 标志图 | 缩略图，缺失时标红提示 |
| 按钮模板 | 张数，点开是缩略图网格，可单独删 |
| 操作 | 上移 / 下移 / 编辑 / 删除 |

- 「新增阶段」在列表顶部，弹窗只有一个输入：名字（标签固定为「中间」，需要时到「编辑」里改）
- 「编辑」可以改名、改标签、换标志图、管理该阶段的按钮模板
- 标志图缺、按钮模板为 0 的阶段用红色标出，与现有的模板加载报告口径一致

**模板制作流程（用户视角）**：

1. 新建场景（英文名，程序自动生成 `01_start_begin`、`02_end_result`）
2. 让游戏停在目标界面，截一张「阶段标志图」，这是判断当前是不是这一页的依据
3. 在同一界面截/导入要点的按钮，作为该阶段的按钮模板
4. 需要中间环节时点「新增阶段」，只填名字（自动建成中间阶段）；默认插在选中行后面，没选中就追加到末尾，落位后编号自动重排
5. 全部阶段做完，启动跑一把，看日志里阶段跳转顺序对不对

**标志图的挑选原则**（做废模板基本都是踩这几条）：

- 选**固定不变的一块 UI**：标题文字、按钮本身、边框、固定图标
- 不要把倒计时、伤害数字、随机角色立绘、动态特效框进去
- 与相邻阶段的标志要有明显差异，两页都有「确定」按钮时，别都拿它当标志
- 短边不要低于 20px，否则会被当成未设置的占位图跳过

**「begin 要点两次」怎么做**：不用建两个阶段。标志图选两次点击时都存在的元素，按钮模板放两张（两次点击的位置），运行时靠「点击后复检、标志仍在就再点」自动连点，点一次就进去的副本也不会多余点击。

**磁盘映射**：阶段直接放在场景目录下，列表每一行对应 `NN_tag_name.png` 与同名目录（不再有 `stages/` 子目录），界面上的增删改排序都会即时落盘，用户手动改文件名也能被识别（下次加载按正则重新解析并校验）。

**兼容与开销**：

- 旧结构（`begin/`、`end/` 两个目录 + 两张标志图）自动映射成 `01_start_begin` / `02_end_result`，行为与现在一致
- 每帧匹配从 2 张变 3~5 张，`detection_scale = 0.5` 下耗时可忽略
- 可点击区域仍按阶段在首次命中时学习一次并缓存（`_regions[阶段]`）

**需要动的地方（当前代码）**：

- `TemplateManager.flags` 只有 `{"begin": (文件名, 图), "end": (...)}`，每阶段固定一张图 → 改为扫描 `stages/`，按 `^(\d+)_(start|end|mid)_([a-z0-9_]+)$` 解析出有序阶段列表（序号、标签、名字）
- `_judge_stage()` 只匹配这两张，返回 `(阶段名, 分数)` → 改为全扫并返回 `(阶段, 序号, 标签, 分数)`
- `_regions` 是 `{"begin": 区域, "end": 区域}`，`_learn_regions()` 每阶段只学一次 → 改为按阶段名/序号缓存
- 战斗计时在第一次点中 end 时就把 `_in_battle` 置 False 并结算时长，多结算页会把战斗时间截短 → 改为命中 `tag=end` 的阶段才结算
- `_begin_cooldown_until` 在 `_click_target()` 里点击那一刻就设好（首次 3 秒）→ 改为复检确认「已经离开该阶段」后再设，否则第二次点击会被自己的冷却挡住
- 新增「点击后复检」：`_click_target()` 点完后置一个待复检标记，下一帧先看同一阶段标志还在不在，在就再点、不在才推进
- `_same_stage_clicks` 现在按 `class_name` 比较 → 改为按阶段序号比较，否则 MVP 页和奖励页会被算成同一个阶段

**异常收尾**（复用现有两套机制，不新增判定）：

- **战斗卡住**：一直在等 end 阶段却等不到（演出卡死、副本特殊）→ 由「战斗超时」（默认 240 秒）收尾，停止并说明原因
- **点击无效**：MVP / 结算页能命中但有东西挡着、点了界面不推进，下一帧又命中同一阶段 → 由「同阶段连击上限」（默认 10 次）判定点击失效或被遮挡，停止并提示
- 两者分工正好互补：**有命中但推不动**走连击上限，**完全没有命中**走战斗超时
- 实现注意：连击计数要按「阶段」统计（阶段序号相同才累加），不能继续按 begin / end 两大类算，否则 MVP 页和奖励页会被算成同一个阶段，上限会被提前触发
