# 痒痒鼠解放双手 使用指南

## 一、怎么打开

找到文件夹里的 **yys_auto.exe**，**双击运行**即可。

> 💡 建议右键 →「以管理员身份运行」，部分电脑不这样做可能点不了游戏窗口。
>
> 💡 首次打开稍慢是正常的。

程序启动后会自动弹出一个浏览器窗口，这就是控制面板，所有操作都在这里完成。

**紧急停止**：按键盘上的 **F12**，所有机器人立刻停。

> ⚠️ **F12 需要控制面板处于最前端才会生效**：按之前先用鼠标点一下控制面板窗口，确保焦点在浏览器里，再按 F12。
> 如果焦点停在模拟器或游戏窗口上，F12 可能不会触发。

## 二、开始之前的准备工作

### ⚠️ 仅支持 MuMu 模拟器

本工具**只适用于 MuMu 模拟器**（MuMu 安卓模拟器），**不兼容阴阳师 MuMu 专版**。请从官网下载普通版 MuMu 模拟器使用。

### ⚠️ 路径不能含中文

模板图片的**完整路径**中只要出现中文字符，程序就读不出来（Windows 下 OpenCV 不支持非 ASCII 路径），表现是模板列表看不到图、或者运行时识别一直失败。

请务必遵守：

- **场景名只能用英文或数字**（场景名就是文件夹名），例如 `chi`、`hunwang`、`999`，不要用「痴」「魂王」这类中文名
- **导入的图片文件名同样不能含中文**，建议用英文或数字
- 程序所在的文件夹路径也建议全英文，避免连带踩坑

> 中文路径支持已列入待修复清单（见「已知问题」第 2 条），在此之前请务必按上述规则命名。

### 你需要准备：按钮截图（模板）

程序是靠"看"屏幕来找按钮的，所以你得先告诉它按钮长什么样。

**方法一：手动导入图片（推荐）**

1. 打开游戏，停在要截按钮的画面
2. 用系统截图工具（`Win + Shift + S`）或 QQ / 微信截图，框选按钮区域
3. 把截图保存为 `.png`，**文件名用英文或数字**
4. 切到控制面板，点「模板管理」页签
5. 左侧选一个场景（没有就点「＋新建场景」，**场景名要英文**）
6. 在 **begin** 或 **end** 那一列点「📁 导入本地」，选中刚保存的图片

- 战斗开始前的按钮 → 存到 **begin**
- 战斗结束后的按钮 → 存到 **end**

> **begin 和 end 截法不一样**：
> - **begin**：只截**按钮本身**，范围越小越好，背景越少越好
> - **end**：截**按钮 + 周围背景**，因为战斗结束画面整体变化大，必须带背景才能稳定识别
>
> | 类型 | 示例 |
> |------|------|
> | begin（只截按钮） | ![begin 示例](templates/chi/begin/QQ20260423-131442.png) |
> | end（按钮+背景）  | ![end 示例](templates/chi/end/QQ20260804-180021.png) |

**方法二：程序自带截图功能（暂不可用）**

点「📷 截取模板」或「📷 截取全屏」后无法正常完成截图流程，请改用上面的方法一。该问题已记录在「已知问题」中。

> **关于「基准图」（baseline）**：程序需要一个场景的**完整窗口截图**作为缩放参照。若某场景显示「未设置」，请用旁边的「📁 导入本地」上传一张游戏窗口的完整截图（**同样注意文件名不要含中文**）。

> **关于「阶段标志」（可选，建议设置）**：给场景的 begin / end 各上传一张**该阶段独有**的界面特征图（**不是按钮图**）。设置后，程序每帧只匹配这两张图来判断当前处于哪个阶段，识别开销与模板数量无关，速度明显更快。要求是「begin 期间它一定在、end 期间它一定不在」（反过来也一样）；**两张都设置**才会启用，缺任一张就自动退回逐模板扫描。
>
> 如何选图：找一处**只在某个阶段出现**、且每轮都在固定位置、不会被动效遮挡的 UI（例如战斗中的状态条、结算界面的标题文字）。设置后首次进入该阶段时程序会全扫一次模板，把能点的位置自动记下来，之后直接在这块范围里随机取点点击。

### 按钮截图要注意什么？

- 截**清晰**的按钮部分，不要带太多背景
- 一个按钮可以存多张图（不同角度、不同状态），提高识别率
- 图片格式用 **.png**

### ⚠️ 关键注意事项

截图模板时，**模板内的每一个像素都可能被脚本点击**。如果截图范围覆盖了能弹出二级界面的区域，一旦误触弹窗遮挡画面，会导致后续识别全部失败。

截图时务必避开以下位置：

| 位置 | 风险区域 | 说明 |
|------|----------|------|
| 右上角 | 聊天入口 | 误点会弹出聊天窗口，遮盖大半画面 |
| 左上 / 中间 | 御魂/式神弹出提示 | 悬浮的御魂图标或式神提示，点开会进入详情界面 |
| 左下角 | Buff 状态栏 | 点击图标可能展开状态详情或叠加界面 |

> 总之截图范围尽量精确，只框住目标按钮本身，不要捎带无关的 UI 元素。

1. 打开游戏，停在准备战斗的界面

## 四、控制面板怎么看

### 每个 Bot 卡片的按钮

| 按钮 | 干什么的 |
|------|----------|
| ▶ 开始 / ⏸ 暂停 / 🔄 继续 | 三合一主按钮，按当前状态自动切换：空闲时是「开始」，运行中变成「暂停」，暂停后变成「继续」。**暂停不会丢统计**，继续后接着累计 |
| ⏹ 停止 | 结束本轮挂机，卡片回到初始状态 |
| ✕ | 删掉这个 Bot |

### 实时数据解释

| 显示 | 意思 |
|------|------|
| 回合 | 已经打了多少次 |
| 均回合 | 平均每回合花了多久 |
| 战斗 | 平均打一次要多久 |
| 耗时 | 已经挂了多少时间 |
| 预计剩余 | 按当前速度，还要多久打完 |

卡片下方的**散点图**展示最近点击的位置分布，绿色是 begin 按钮，蓝色是 end 按钮。背景里的**半透明轮廓**是程序为该阶段识别出的「可点击范围」（绿=begin、蓝=end）—— 正常情况下散点都落在同色轮廓内；如果点跑到轮廓外面，说明范围学习得不准或识别出了异常，可以重新截一次模板或阶段标志。

### 战斗次数

每个 Bot 卡片上可以单独设置「战斗次数」，比如设 10 次，打完就自动停止。

## 六、参数配置（一般不用改）

切换到「⚙ 参数配置」页签可以调整一些高级设置。

### 匹配阈值

默认 **0.75**。

| 情况 | 怎么调 |
|------|--------|
| 按钮经常识别不到 | 调低（如 0.65） |
| 经常点到别的地方 | 调高（如 0.85） |

### 休息设置

| 设置 | 默认 | 说明 |
|------|------|------|
| 每打N把休息 | 50 | 挂多少轮后自动歇一会 |
| ± 浮动 | 10 | 不会每次都刚好 50 把，会随机浮动（更自然） |
| 休息时长 | 30 秒 | 每次歇多久 |
| ± 浮动 | 5 秒 | 休息时间也会随机浮动 |

### 鼠标速度

| 设置 | 默认 | 说明 |
|------|------|------|
| 最小速度 | 2750 | 鼠标移动速度下限，越低越拟人 |
| 最大速度 | 3250 | 鼠标移动速度上限 |

### 扫描与保护

| 设置 | 默认 | 说明 |
|------|------|------|
| 连续未匹配上限 | 20 | 连续这么多次没匹配到，就停顿一下再重试（最多 3 轮），减少无效空转 |
| 未匹配延时 | 2 秒 | 上面每次停顿要等多久 |
| 同阶段点击上限 | 10 | 连续点了同一阶段这么多次、界面还是没变化，就判定为被遮挡或点击失效，自动停止运行（填 0 关闭该保护） |

### 其他设置

| 设置 | 默认 | 说明 |
|------|------|------|
| 消抖帧数 | 2 | 识别到按钮后，连续确认几帧才点击。调大减少误触，但反应变慢 |
| 识图缩放 | 0.5 | 截图缩小到一半再识别，加快速度。不建议改 |
| 屏幕区域 | 0~1920 / 0~1080 | 限定截图范围，一般缩小到游戏窗口大小即可 |

## 七、常见问题

### 打开程序没反应？

系统需要 **Edge 浏览器**，Win10 / Win11 自带，不用担心。

### 按钮识别不到？

1. 检查**场景名和图片文件名是否含中文** —— 只要含中文就会直接读不到（见上文「路径不能含中文」）
2. 检查模板是否放对了场景目录
3. 把「匹配阈值」调低一些
4. 多截几张不同状态的按钮图

### 点「📷 截取模板」没反应？

自带截图功能当前不可用（见「已知问题」第 3 条），请用系统截图工具（`Win + Shift + S`）裁剪后，通过「📁 导入本地」上传。

### 挂了没多久就自己停了？

翻一下卡片上的日志，如果结尾是「连续 N 次点击 xx 阶段后界面无变化，判定为点击失效或被遮挡」，说明有东西挡住了画面（常见是弹出的二级界面、聊天窗口、系统通知），程序为了避免继续乱点会主动停下。

- 手动关掉弹窗，再点「开始」即可
- 如果每轮都这样，多半是**游戏界面变了**导致模板或阶段标志过期，重新截一次即可
- 嫌它太敏感，可以把「同阶段点击上限」调大，或填 `0` 关闭该保护

### 设置了阶段标志，反而识别不到了？

说明标志图选得不够"独有"。要求是 **begin 期间它一定在、end 期间它一定不在**（反过来也一样）：

- 别用按钮图当标志，要选该阶段独有的界面元素（状态条、结算标题之类）
- 太小的图标容易被动效或遮挡影响，选**大一点、颜色稳定**的区域
- 一时找不到合适的图可以先不设 —— 留空时会自动退回逐模板扫描，功能和以前一样

### 鼠标不动或点不对位置？

- 试试右键以**管理员身份**运行
- 部分游戏需要在显示设置里关掉"硬件加速"

### 杀毒软件报警？

正常现象。程序需要模拟鼠标和监听键盘，安全软件可能误会。添加到信任列表就好。

## v1.2（2026-09-26）

- 🐛 **修复「暂停后恢复会清空统计数据」**：根因是「继续」按钮复用了「开始」按钮的处理器，点击时调用的是 `start_bot` 而非 `resume_bot`；后端 `start()` 对 `paused` 状态不拦截，于是重建了新的 Bot 实例，统计随之归零，同时旧线程未被回收，出现新旧两个线程同时操作同一窗口的隐患。现改为独立的 `toggle_bot` 接口，由后端按实例真实状态分派，前端不再参与状态判断
- ⚡ **识别算法优化：阶段旗帜判阶段 + 可点击区域学习**（原「优化想法」中的方案已落地）：为场景配置 `begin.png` / `end.png` 两张**阶段旗帜**后，每帧只做 **2 次模板匹配**就能判定当前阶段，扫描开销与模板总数无关（此前需逐模板扫描全图）。首次进入某阶段时全扫该阶段所有模板一次，把命中的框**自适应内缩**（避开框边缘的相邻 UI，begin / end 分别取值）、填缝后合并成一份**可点击区域**；之后每次进入该阶段，直接在这块区域里**按面积等概率随机取一个像素**点击 —— 既省掉重复扫描，点击位置也天然发散。未配置旗帜的场景自动退回原全图扫描逻辑，行为不变。配套新增「同阶段点击上限」保护：连续点同一阶段过多次而界面始终无变化时，判定为被遮挡或点击失效，自动停止运行
- ✨ 运行控制简化为两个按钮：主按钮在「开始 ↔ 暂停 ↔ 继续」之间随状态自动切换文案与配色，停止按钮无论当前什么状态都回到初始
- 🔧 `stopping` 期间主按钮禁用；重建实例前先在锁外回收旧线程，避免并发与死锁
- 🔧 **配置文件拆分**：`config.json` 不再纳入版本管理（其中含窗口名等本机信息），改由 `config.example.json` 提供样例；首次运行时若缺少 `config.json`，会自动从样例复制一份
- 🔧 鼠标移动速度默认值由 2500 / 3000 调整为 **2750 / 3250**
- 📝 文档更新：教程新增「路径不能含中文」警告、截图改用「导入本地」；「自带截图功能不可用」列入已知问题；运行控制说明同步为双按钮
- 🐛 **修复运行中移动窗口后点击分布图错位**：点击点此前记录的是点击那一刻的**屏幕绝对坐标**，而前端绘图时用**最新**的窗口位置去还原，两个时间点不一致 —— 移动窗口后历史点会整体平移（偏移量正好等于窗口移动距离），移出绘图区的还会被直接丢弃。现改为记录**窗口内相对坐标**，与窗口在屏幕上的位置彻底解耦；停止后生成的 matplotlib 统计图同步修复（此前若移动过窗口，散点会分成两簇分别对应两个位置）
- ✨ **点击分布图叠加可点击范围**：把两个阶段学习到的「可点击区域」以轮廓线画在散点图背景上（绿=begin、蓝=end）。轮廓由后端用 `findContours(RETR_CCOMP)` 合并而成 —— 相邻区域自动连成一片，重叠处不加深、也不出现内部边线，区域里的**内部空洞**同样会画出内轮廓。前端把所有轮廓放进同一条路径，`fill("evenodd")` + `stroke()` 各只调一次。点击点应落在同色轮廓内；跑到轮廓外说明范围学习不准或识别异常，一眼可辨
- ⚡ **日志文件按体积轮转**：`logs/yys_auto.log` 由无限追加改为 `RotatingFileHandler`（单文件 5 MB、保留 3 份），长时间挂机不再让日志无限膨胀
- ⚡ **学习可点击区域前等待过渡动画结束**：首次进入某阶段要全扫模板建立可点击区域，此前若界面还在过渡动画中，中间帧的匹配结果会被一并学进范围；现在学习前先等 1 秒（可中断，暂停/停止会立即响应），待画面稳定后再学
- 🔧 **可点击范围的内缩量按阶段区分**：begin 单独调小（8px / 10%，end 仍为 25px / 35%）—— begin 模板一般只框按钮本身、截图精确，沿用 end 的内缩量会让可点击范围明显偏小
- ⚡ **连续同阶段的点击前复核阶段标志**：坐标是识别阶段时算好的，从判定到真正点击之间界面可能已经开始切换，因而点到错误的区域。现在「连续点击同一阶段」时会在点击前重新截一帧复核标志，不通过就丢弃这次点击；**首次进入某阶段不作复核**（标志刚确认过），避免白白多一次截图。开关见脚本顶部 `STAGE_RECHECK_ENABLED`

# 发版打包

## 版本号约定

- **打包前**：所有未发布的改动都记在**同一个版本号**下，后续改动继续往该版本追加条目
- **打包后**：该版本号冻结，之后的改动开**下一个版本号**
- README 顶部的「当前版本」始终指向**正在开发中**的那个版本

> 例：v1.1 打包发布后 → 之后所有改动都写进 v1.2 → v1.2 打包后 → 再开 v1.3

## 目录约定

所有发布版本统一归档在 `Mycodes/yys_auto_app/` 下，按版本号建目录：

```
Mycodes/
├── yys_auto/                  ← 源码仓库
└── yys_auto_app/              ← 发布目录
    ├── yys_auto_v1.0/        历史版本
    ├── yys_auto_v1.1/        历史版本
    └── yys_auto_v1.2/        当前版本
```

每个版本目录内含：

```
yys_auto_v1.2/
├── yys_auto.exe      ← 双击运行
├── _internal/        ← 程序依赖，不要动
├── config.json       ← 配置（前端保存时自动写这里）
├── templates/        ← 模板截图
├── logs/             ← 运行日志
└── README.md         ← 本说明
```

## 打包命令

```powershell
cd c:\MyAPPs\Mycodes\yys_auto
.\build.ps1 -Version 1.2
```

版本号**只写数字**（`1.2`，不是 `v1.2`）。脚本会自动完成：

1. 调用 PyInstaller，输出到 `yys_auto_app/yys_auto_v1.2/`
2. 清理发布根目录残留的中间 exe
3. 复制 `config.example.json`、`README.md`、`templates/` 进发布目录（**不含**本机 `config.json`，用户首次运行会自动生成）
4. 创建空的 `logs/` 目录

目标目录已存在时会直接报错，避免误覆盖旧版本。

## 手动打包（等价命令）

```powershell
cd c:\MyAPPs\Mycodes\yys_auto
$env:YYS_APP_VERSION = '1.2'
pyinstaller yys_auto.spec --distpath ../yys_auto_app --workpath build --noconfirm
```

输出目录名由 `yys_auto.spec` 里的 `COLLECT(name=f'yys_auto_v{_VERSION}')` 决定，版本号经环境变量 `YYS_APP_VERSION` 传入（未设置时为 `dev`）。

> 打包中间产物 `build/` 会保留在源码目录，可加速下次打包；不需要时直接删除即可（已在 `.gitignore` 中忽略）。

# 已知问题

> 以下问题当前版本尚未修复，仅作记录。

## 1. 程序存在最大存活时间，超时后失去连接

**现象**：程序持续运行一段时间后会失去连接（前端控制面板无响应 / 状态轮询失败），需重启程序才能恢复。

**影响**：长时间挂机场景下无法稳定运行，需要人工干预重启。

**排查方向**：

- Eel / WebSocket 连接超时或内存泄漏
- 日志缓冲区无限增长导致内存耗尽
- 长时间运行后句柄/资源未释放
- gevent 相关的定时器或 keep-alive 机制超时

## 2. 中文路径下模板图无法读取

**现象**：模板图片路径包含中文字符时（如场景名「痴」对应的 `templates/痴/...` 目录），程序无法正常读取模板图，识别失败。

**影响**：场景目录使用中文名时功能异常，只能用英文命名场景规避。

**排查方向**：Windows 下 OpenCV（`cv2.imread`）不支持非 ASCII 路径，可改用 `cv2.imdecode(np.fromfile(path, dtype=np.uint8), flag)` 读取，模板加载与截图保存两处需统一处理。

## 3. 自带的截图功能无法使用

**现象**：在「模板管理」页签点「📷 截取模板」或「📷 截取全屏」，无法正常完成截图流程（新窗口打开后看不到截图 / 框选无反应 / 保存失败）。

**影响**：只能用「📁 导入本地」手动导入截图，步骤更繁琐。

**当前规避**：用系统截图工具（`Win + Shift + S`）或 QQ / 微信截图，裁剪后通过「📁 导入本地」上传。

**排查方向**：

- `screenshot_screen()` 把整屏 PNG 编码成 base64 后经 WebSocket 传输（1080P 下约 2~5 MB），可能超时或超出载荷限制
- `minimize_self()` 依赖窗口标题含 `127.0.0.1` 或 `eel` 才最小化；标题不匹配时不生效，截到的是浏览器而非游戏画面
- 系统显示缩放（DPI）非 100% 时，截图尺寸与坐标可能对不上
